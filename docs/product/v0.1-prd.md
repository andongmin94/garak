# Garak v0.1 Product Requirements

- 문서 상태: Phase 0A 제품 범위 기준선
- 최종 갱신: 2026-08-09
- 관련 문서: [제품 비전](vision.md), [사용자와 사용 사례](users-and-use-cases.md), [Phase 0A ExecPlan](../../plans/0001-phase-0a-repository-foundation.md)

## 문서의 역할

이 문서는 Garak v0.1이 해결할 문제, 포함 범위, 명시적 비범위와 제품 수용 경계를 정의한다. Phase 0A에서는 구현을 승인하거나 완료를 주장하지 않는다. 세부 architecture와 milestone은 이 범위를 충족해야 하며, 기술 spike 결과가 제품 범위 변경을 요구하면 그 이유와 영향을 문서와 ADR에 먼저 기록해야 한다.

“사업 정책 가설” 절은 제품 방향을 검토하기 위한 기준이지 이용약관, 라이선스 계약, 지식재산권 판단 또는 법률 자문이 아니다.

## 제품 정의

Garak은 아티스트가 sound graph, 공개 parameter와 macro, plugin interface, preset, metadata와 brand identity를 하나의 product project로 설계하고 독립적인 native audio effect로 export하는 Windows/macOS 제작 플랫폼이다.

v0.1은 아티스트 시그니처 컬러 이펙트와 채널 스트립을 끝까지 만드는 한 경로에 집중한다. 범용 DSP 언어, instrument builder 또는 plugin marketplace를 목표로 하지 않는다.

## v0.1 목표

아티스트 또는 작은 제작 팀이 다음 흐름을 한 제품에서 완주할 수 있어야 한다.

1. mono/stereo audio effect의 static DSP graph를 구성한다.
2. 내부 parameter를 공개 parameter와 감각적인 macro에 mapping한다.
3. 실제 음원으로 sound와 control response를 audition한다.
4. plugin-focused interface와 parameter/meter binding을 만든다.
5. default state, preset, asset와 product metadata를 완성한다.
6. Windows/macOS native plugin으로 export하고 Studio가 없는 환경에서 사용한다.

첫 수직 증거는 `ANDONGMIN — BLOOM`이다. 단순히 별도 기능이 존재하는 것만으로는 v0.1 목표를 충족하지 않으며, 이 reference product가 authoring부터 DAW 사용까지 같은 계약을 따라야 한다.

## 포함 범위

### 만들 제품

- 아티스트 시그니처 컬러 이펙트
- 아티스트 시그니처 채널 스트립
- mono/stereo audio effect
- warmth, bloom, saturation, glue, air, softness, density 같은 캐릭터를 만드는 제품
- 복잡한 내부 처리를 소수의 공개 macro로 재해석한 제품

### Studio authoring

- Windows와 macOS Garak Studio
- no-code DSP graph authoring과 graph validation
- internal parameter, public parameter와 macro mapping
- mapping range, default와 curve 편집
- plugin interface 제작과 binding
- default state와 preset 제작
- product name, identity, stable ID, asset와 metadata 편집
- 실제 audio material을 사용한 audition과 preview
- validation과 export 진입점

### Interface Designer

v0.1은 plugin UI에 필요한 다음 기능 범주에 집중한다. 항목별 상세 동작과 완성 기준은 구현 ExecPlan에서 좁혀야 한다.

- frame, group와 layer
- shape, text, image와 SVG
- fill, stroke, gradient와 shadow
- alignment, snap와 grid
- 기본 auto layout
- reusable component와 instance
- knob, slider, toggle, meter와 preset menu
- parameter, macro와 meter binding

### 생성 제품과 format

- 독립적인 VST3 export
- Windows x64 VST3
- macOS arm64/x86_64를 포함한 Universal VST3
- VST3 경로 검증 이후 macOS AU
- 생성 플러그인의 offline operation
- Garak Studio가 없는 컴퓨터에서의 독립 실행
- 제품 UI에 Garak branding을 강제하지 않는 white-label export

기술 검증 순서는 Windows x64 VST3, macOS arm64/x86_64 VST3, macOS AU이다. 순서는 scope 제외를 뜻하지 않는다. 첫 상용 v0.1 목표는 Windows VST3, macOS Universal VST3와 macOS AU를 모두 포함한다. 앞 단계의 format만 통과한 build는 기술 milestone일 수 있으나 전체 v0.1 출시 수용을 충족하지 않는다.

### Runtime behavior

- 실시간 DSP graph 실행
- parameter smoothing과 host automation
- bypass와 latency/buffer 관리
- preset, plugin state 저장과 restore
- native plugin UI runtime
- stable product/plugin/parameter identity
- versioned project, runtime state와 DSP node implementation
- 이전 project, preset과 DAW state를 다루는 migration 경로

## Reference product — ANDONGMIN — BLOOM

### 제품 의도

`ANDONGMIN — BLOOM`은 vocal 또는 instrument에 따뜻함, 밀도와 부드러움을 부여하는 아티스트 시그니처 컬러 플러그인이다. v0.1 기능을 따로 시연하는 demo가 아니라 Garak의 전체 수직 경로를 검증하는 reference product이다.

### 내부 처리 개념

다음은 graph와 macro 능력을 검증하기 위한 현재의 처리 개념이며, Phase 0A에서 알고리즘, node 종류, 순서 또는 음향 결과를 확정하는 DSP 명세가 아니다.

```text
Input
→ Gentle Compression
→ Harmonic Saturation
→ High-frequency Softening
→ Low-mid Density
→ Output Compensation
→ Dry/Wet
→ Output
```

### 공개 컨트롤 기준안

- Bloom
- Warmth
- Softness
- Mix
- Output

이 이름은 artist-facing control language와 one-to-many macro mapping을 검증하는 기준안이다. 최종 range, unit, default, curve와 내부 mapping은 listening test와 구현 계획에서 확정한다. 출시된 numeric parameter ID는 이후 변경하거나 재사용할 수 없으므로 release 전에 별도 검토가 필요하다.

### BLOOM이 반드시 증명할 수직 경로

- sound graph authoring과 compile
- 여러 내부 parameter를 다루는 macro mapping
- interface scene과 control/meter binding
- host parameter automation과 smoothing
- default state, preset 저장과 restore
- stable product metadata와 identity
- Windows/macOS package 생성과 format validation
- Studio가 없는 환경에서의 independent plugin operation

## 기능 요구사항

| ID | 요구사항 | v0.1 관찰 가능한 결과 |
| --- | --- | --- |
| PRJ-01 | 하나의 versioned `.garak` project가 제품의 editable source of truth여야 한다. | Project를 저장하고 다시 열었을 때 graph, mapping, interface, preset, asset reference와 metadata가 복원된다. |
| SND-01 | 사용자는 지원되는 node로 mono/stereo static DSP graph를 만들고 validate할 수 있어야 한다. | 잘못된 port, 허용되지 않는 cycle 또는 지원되지 않는 graph는 export 전에 설명 가능한 오류로 거부된다. |
| CTL-01 | 공개 parameter와 macro는 내부 parameter 하나 이상에 range와 curve로 mapping될 수 있어야 한다. | Control 변화가 저장된 mapping대로 반영되고 실제 audio processing과 UI binding에서 같은 의미를 갖는다. |
| CTL-02 | 공개 parameter는 smoothing, automation과 stable numeric ID 계약을 따라야 한다. | Host automation이 처리되고 저장 후 복원되며 출시된 ID가 변경되거나 재사용되지 않는다. |
| AUD-01 | 사용자는 실제 audio material로 product sound를 audition할 수 있어야 한다. | Studio에서 graph, mapping과 preset 변경의 처리 결과를 재생하고 비교할 수 있다. |
| UI-01 | 사용자는 plugin-focused scene을 만들고 control과 meter를 product data에 bind할 수 있어야 한다. | Export된 native UI에서 layout, visual state와 binding이 의도한 product model을 따른다. |
| PST-01 | 사용자는 default state와 preset을 만들고 복원할 수 있어야 한다. | Studio, exported plugin과 host state round trip에서 지원되는 state가 재현된다. |
| META-01 | Product에는 영구 product ID와 plugin class ID 및 필요한 format metadata가 있어야 한다. | 같은 제품의 update가 identity를 유지하고 다른 제품과 충돌하지 않는다. |
| EXP-01 | Studio는 product를 지원되는 native plugin package로 validate하고 export해야 한다. | 목표 format package가 생성되고 해당 platform의 검증 절차와 실제 host smoke test를 통과한다. |
| RUN-01 | 생성 플러그인은 Garak Studio나 네트워크 연결 없이 기본 기능을 수행해야 한다. | 깨끗한 offline system에서 load, audio processing, UI, preset과 state restore가 작동한다. |
| RUN-02 | 생성 플러그인은 Electron, Chromium, Node.js 또는 임의의 JavaScript runtime을 포함하지 않아야 한다. | Package dependency와 binary inspection으로 금지 runtime 부재를 확인한다. |
| BRD-01 | 생성 제품은 아티스트의 name, brand와 asset을 사용하고 Garak branding을 강제하지 않아야 한다. | Product UI와 기본 metadata에 의무적인 “Made with Garak” 요소가 없다. |
| CMP-01 | Schema와 sound-changing node behavior는 versioning 및 migration 계약을 따라야 한다. | 지원 대상의 이전 project, preset과 DAW state를 명시적인 migration test fixture로 검증한다. |

구체적인 지원 node 목록, host matrix, project schema와 scene property는 후속 architecture/implementation 문서에서 정의한다. 아직 정하지 않은 세부를 이 표가 암묵적으로 보장하지 않는다.

## 품질 및 장기 계약

### 실시간 처리

향후 audio process callback에서는 다음을 허용하지 않는다.

- 동적 메모리 할당
- mutex 또는 blocking lock
- 파일 또는 네트워크 I/O
- JSON parsing
- GUI 호출
- 로그 파일 기록
- 예외 전파
- graph 구조 변경
- 실행 시간이 예측 불가능한 blocking operation

필요한 memory, audio buffer, execution schedule와 converter는 prepare/compile 단계에서 준비한다. CPU, latency, denormal, sample-rate, channel-layout와 stress-test의 정량 기준은 첫 native runtime 구현 전에 별도 품질 계획으로 확정해야 한다.

### 장기 호환성

- 각 제품은 영구 product ID와 plugin class ID를 가진다.
- 출시된 parameter numeric ID는 변경하지 않는다.
- 삭제된 parameter ID는 재사용하지 않는다.
- DSP node implementation을 명시적으로 versioning한다.
- 소리가 달라지는 변경은 기존 node version을 덮어쓰지 않고 새 version으로 추가한다.
- `.garak` project와 runtime state는 schema version을 가진다.
- 이전 project, preset과 DAW state에는 명시적인 migration 체계를 둔다.

v0.1 출시 전에 실제로 지원할 과거 version의 범위, migration 실패 정책과 호환성 지원 기간을 별도로 정해야 한다. “migration 체계가 있다”는 요구가 무기한 호환성을 의미하지 않는다.

### Native 독립성

Studio는 Electron/React/TypeScript strict mode를 사용한다. Native Engine과 생성 plugin runtime은 C++20을 사용하고 CMake/Ninja로 빌드하며 JUCE를 사용하지 않는다. Studio 기술 선택이 생성물의 설치 요구사항으로 누출되어서는 안 된다.

### 외부 의존성 경계

`.garak` model, graph/node contract, compiler/schedule, buffer planning, parameter/macro, state migration, interface scene, product compiler, generated runtime contract와 validation/export pipeline은 Garak이 소유한다. 외부 library와 SDK는 adapter 뒤에 격리하며 그 타입을 Garak public API에 노출하지 않는다.

Steinberg VST3 SDK, Skia, CanvasKit, Yoga, XYFlow, miniaudio, KissFFT와 FlatBuffers는 후속 적합성 검증 후보일 뿐 v0.1의 확정 의존성이 아니다.

## 사업 정책 가설

> **중요:** 이 절은 Phase 0A의 제품 및 사업 방향 가설이다. 완성된 이용약관, 소프트웨어 라이선스, 소유권 판정, 재배포 허가 또는 법률 자문이 아니며 어떤 권리도 그 자체로 부여하거나 보증하지 않는다. 실제 출시 전 관할 법률, third-party license와 계약 문구에 대한 전문 검토가 필요하다.

현재 기본 가설은 다음과 같다.

- 사용자가 직접 만든 DSP graph, macro와 preset은 사용자 창작물로 취급하는 방향이다.
- 사용자가 직접 만든 interface와 asset은 사용자 창작물로 취급하는 방향이다.
- 제품명, brand와 artist identity는 사용자에게 귀속되는 방향이다.
- 사용자는 자신이 적법한 권리를 가진 material로 생성한 플러그인을 판매할 수 있게 하는 방향이다.
- 생성 플러그인 매출에 대한 지속적인 Garak royalty는 기본적으로 부과하지 않는 방향이다.
- Garak Runtime 재배포 권한은 향후 Garak Studio license에 포함하는 방향이다.
- 최종 제품 화면에 Garak branding을 강제하지 않는 방향이다.

각 가설은 사용자가 투입한 third-party code, font, image, sample, trademark와 기타 material의 권리를 Garak이 보증한다는 뜻이 아니다. 저장소 자체의 license, Studio license, generated runtime redistribution terms, trademark policy, third-party notice 의무, support/update 의무와 판매 지역은 아직 정하지 않았다. 이 저장소 문서만을 근거로 상용 배포를 허용해서는 안 된다.

## v0.1 수용 경계

### 전체 v0.1을 수용하기 위한 필수 증거

다음 항목은 구현 완료 주장만이 아니라 재현 가능한 검증 증거가 있어야 한다.

1. `ANDONGMIN — BLOOM` project를 Studio에서 열고 sound graph, macro, interface, preset과 metadata를 편집·저장·복원할 수 있다.
2. 실제 vocal 또는 instrument audio로 BLOOM을 audition하고, compiled/exported runtime과 비교하는 검증 경로가 있다.
3. Bloom, Warmth, Softness, Mix와 Output control이 명시적인 mapping/default/curve를 가지며 host automation과 smoothing을 통해 처리된다.
4. Plugin state와 preset을 저장한 뒤 plugin reload 및 DAW session reopen에서 지원 범위의 상태가 복원된다.
5. Windows x64 VST3, macOS Universal VST3와 macOS AU package가 생성되고, 각 target의 공식 validator와 실제 host smoke test를 통과한다.
6. 생성 package가 Garak Studio 없이 offline에서 audio processing, UI, preset과 state restore를 수행한다.
7. 생성 package에 Electron, Chromium, Node.js 또는 임의의 JavaScript runtime이 없음을 dependency/binary inspection으로 확인한다.
8. Product UI와 metadata에 의무적인 Garak branding이 없고 아티스트의 product identity가 적용된다.
9. 영구 product/plugin/parameter ID, node version과 schema migration 규칙이 fixture와 compatibility test로 검증된다.
10. 지원 OS, CPU architecture, plugin format, DAW/validator version, 알려진 제한과 설치 조건이 실제 검증 결과대로 문서화된다.

정확한 audio quality, CPU/latency budget, preview parity tolerance와 supported DAW/OS matrix는 아직 미정이다. 이 값들은 출시 전에 측정 가능한 기준으로 정해져야 하며, 미정인 채로 전체 v0.1을 PASS 처리할 수 없다. Accessibility 범위와 기준은 아직 v0.1 요구로 승인되지 않은 Open Question이다.

### 전체 v0.1 수용으로 간주하지 않는 것

- Studio shell, graph editor mockup 또는 UI prototype만 존재하는 상태
- Studio preview에서만 소리가 나고 독립 plugin export가 없는 상태
- Plugin이 load되지만 automation, preset 또는 state restore가 검증되지 않은 상태
- 생성 plugin이 Studio 설치, network 또는 JavaScript runtime에 의존하는 상태
- Windows VST3 하나만 통과한 기술 spike를 전체 commercial target 완료로 보고하는 것
- BLOOM 대신 서로 연결되지 않은 unit demo만 존재하는 상태
- Validator/host test를 실행하지 않고 통과했다고 기록하는 것
- 법률 검토 없이 사업 정책 가설을 확정된 판매·재배포 권한으로 표현하는 것

## Phase 0A 수용 경계

현재 단계는 specification freeze이다. 이 PRD, 제품 비전과 사용자 문서가 범위·용어·미결정 사항을 일관되게 기록하고, 실제 DSP/UI/export 구현이나 외부 dependency를 추가하지 않았을 때만 제품 문서 작업이 완료된다. v0.1 기능 요구사항은 향후 작업을 위한 기준이지 Phase 0A에서 구현된 기능이 아니다.

- Studio audition에 필요한 audio device, transport, file format과 A/B comparison의 최소 기능은 무엇인가?

### 품질과 호환성

- 지원할 Windows/macOS 최소 version과 검증할 DAW/host matrix는 무엇인가?

- Crash isolation, invalid project recovery와 export diagnostic의 최소 기준은 무엇인가?

### Export와 runtime
